# Phase 4 (rest of the first release) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything in the design's "Scope of the first release" works: the
fuzzy room picker (also for rooms with mentions), mute and unmute, opening
links and attachments, uploading files, and images in the message view.

**Architecture:** The core owns the room picker (a second `PickerKind`), the
targets of mute, open and upload, and the image request for the message
view. The matrix adapter changes notification settings, downloads and
uploads media. The terminal adapter runs the opener, decodes and scales
images, and draws them in the message view with ratatui-image.

**Tech Stack:** Rust 2024, matrix-sdk 0.19 (notification settings, media,
`Timeline::send_attachment`), `mime_guess` 2, `image` 0.25, `ratatui-image`
11.

## Global Constraints

- The design is `docs/superpowers/specs/2026-11-18-mxt-design.md`. It wins over
  this plan when they disagree.
- Everything in the repository is in English. Tests use made-up identifiers.
- `mxt-core` stays free of I/O; media bytes pass through it as an opaque
  `MediaBytes` (`Arc<[u8]>`) it never decodes (design, "Functional core").
- Writes to the real account only in the test room, by the orchestrator.
- `ratatui-image = { version = "11", default-features = false, features =
  ["crossterm"] }` and `image = { version = "0.25", default-features = false,
  features = ["png", "jpeg", "gif", "webp"] }`: the defaults pull in a
  license the policy rejects (rav1e, libfuzzer-sys) and a native library
  (chafa).
- Dependencies once in the root `[workspace.dependencies]`; cargo in
  `nix develop`; matrix-sdk builds under the shared lock.

### Task 1: Room picker, mute targets, open and upload actions in the core

**Files:** `crates/mxt-core/src/app/picker.rs`, `app/rooms.rs`,
`app/timeline.rs`, `effect.rs`, `msg.rs`, `timeline.rs`, tests.

**Interfaces (additions):**

```rust
PickerKind::Rooms { filter: RoomFilter }
PickerKind::Links   // the links of the item under the cursor; keys are the URLs
/// Items carry their room, so two rooms with the same displayed name are
/// both reachable (review of #12).
PickerItem { label: String, key: String }   // key: the room ID for room items

MatrixEffect::SetMute { room: RoomId, muted: bool },
MatrixEffect::Download { room: RoomId, item: ItemRef },
MatrixEffect::Upload { room: RoomId, path: String },
MatrixEffect::FetchImage { room: RoomId, item: ItemRef },

Msg::Downloaded { path: String },
Msg::ImageFetched { item: ItemRef, bytes: MediaBytes },
Msg::ImageUnavailable { item: ItemRef, reason: String },

UiEffect::OpenPath(String),      // run `files.opener` with the path appended
UiEffect::OpenUrl(String),       // run `files.opener` with the URL appended
UiEffect::OpenView(ViewContent), // gains ViewContent::Image { item, name, size, dimensions }
UiEffect::ShowImage { item: ItemRef, bytes: MediaBytes },

pub struct MediaBytes(Arc<[u8]>);   // opaque; Clone; Debug prints only the length
```

**Behavior:**
- `picker.rooms` (with `filter`): opens the room picker; items are the rooms
  that pass the filter, labelled with the displayed name and the badge, in
  room list order for an empty query and ranked with `fuzzy::rank` on the
  displayed name otherwise; `picker.accept` opens the selected room by its
  ID (as `room.open` does: unsubscribe/subscribe, focus the timeline).
  `<leader>m` is the mentions filter (design, "Mentions"). An empty item list
  shows `No matching room` in the picker.
- `room.mute` / `room.unmute` (and `:mute`/`:unmute`): target as for
  `room.mark_read` (the room under the cursor in the room list, else the
  open room); `SetMute { muted }`; status `Muted <name>` / `Unmuted <name>`.
  The mode label changes when the SDK reports the new mode.
- `message.open` (`gx`) on the item under the cursor: an image or file
  attachment → `Download`; then `Msg::Downloaded { path }` →
  `UiEffect::OpenPath(path)` and status `Saved <path>`. Otherwise the links
  of its `RichText`: none → status `Nothing to open`; one →
  `UiEffect::OpenUrl`; several → a picker of the link URLs
  (`PickerKind::Links`), accept → `OpenUrl`.
- `file.upload` (`:upload <path>`): needs an open room; `Upload { path }`;
  failures arrive as `EffectFailed`.
- `message.view` on an image item: `OpenView(Image { .. })`, and unless
  `Settings::image_preview` is `Off`, `FetchImage`. `ImageFetched` for the
  item the open view shows → `UiEffect::ShowImage`; for any other item it is
  dropped. `ImageUnavailable` → status with the reason.

**Tests:** picker items, ranking, filter and accept by ID (two rooms with the
same name both reachable); mute targets and status; `gx` on a file, on one
link, on several links, on nothing; upload without a room; the image view
with preview on and off; a late `ImageFetched` for a closed view is dropped;
`MediaBytes` Debug does not print bytes.

- [ ] Steps: failing tests, see them fail, implement, pass, fmt and clippy,
  commit ("Add the room picker, mute, open, upload and the image view to the core").

### Task 2: Notification modes, downloads, uploads and image fetching in the matrix adapter

**Files:** `crates/mxt-matrix/src/adapter.rs`, a new `media.rs`; the
configuration's `files.download_dir` reaches the adapter through
`Matrix::start`.

**Behavior:**
- `SetMute { muted: true }` → `notification_settings().set_room_notification_mode(room, Mute)`;
  `muted: false` → `delete_user_defined_room_rules(room)` (design, "Mute").
- `Download`: the item's media source (`MediaSource`, encrypted or not) via
  `client.media().get_media_content(&MediaRequestParameters { source, format: File }, true)`;
  the file name from the event, made safe (no path separators, no leading
  dot); saved in `download_dir` with the design's collision rule
  (`name (1).ext`, `name (2).ext`, …; a pure function with tests); written
  with `create_new`; then `Msg::Downloaded { path }`.
- `Upload`: read the file, guess the MIME type with `mime_guess` (fallback
  `application/octet-stream`), send with `Timeline::send_attachment` (image
  for `image/*`, file otherwise) in the open room's timeline, or the room's
  own when no timeline is open.
- `FetchImage` (design, "Images"): the thumbnail source when the event has
  one, else the file; refuse files larger than 10 MB (`ImageUnavailable`
  with `too large to preview`); `Msg::ImageFetched` with `MediaBytes`.
- Tests: the collision rule and the safe file name; the size check.

- [ ] Steps: tests, implement, pass (under the lock), fmt and clippy, commit
  ("Mute and unmute rooms, download, upload and fetch images in the matrix adapter").

### Task 3: Opener and images in the terminal adapter

**Files:** `crates/mxt-tui/src/` (a new `image_view.rs`, `terminal.rs`,
`view.rs`); root `Cargo.toml` (`image`, `ratatui-image` as in the global
constraints).

**Behavior:**
- `OpenPath`/`OpenUrl`: spawn `files.opener` with the argument appended,
  detached (stdin, stdout and stderr null), never waiting on it; a spawn
  failure becomes `Msg::EffectFailed`.
- The room picker and link picker reuse the emoji picker's overlay.
- Image view (design, "Files and images"): the message view shows the name,
  size and dimensions, and with `ShowImage` the image decoded with `image`,
  scaled down to the view, drawn with ratatui-image (`Picker::from_query_stdio`
  once at startup for the protocol: sixel, kitty, iTerm2, else half blocks),
  cached per item in a small cache (the last few images). Images are never
  drawn in the scrolling timeline.
- Verify by running (throwaway example): a PNG and a JPEG in the view under
  tmux (half blocks there), and the opener with `files.opener = ["echo"]`.

- [ ] Steps: unit tests for the cache and the opener argument building,
  implement, verify by running, fmt and clippy, commit
  ("Open files and links, and show images in the message view").
